## 2026-11-17 22:13:43 -0500 — G2: GDTF library RDM data and matching, server side (`feat/gdtf-g2-rdm`)

**Why:** plan chunk G2 (`docs/plans/gdtf-library-brief_2026-11-17_2101.md`): match a discovered RDM device to a downloaded GDTF file and name its personality's mode; and search LongName, which getList does not carry. Built by a delegated agent from the coordinator's brief.

**Spec** (gdtf-spec.md, github.com/mvrdevelopment/spec @ 098d3791f77f0895bd859adf01864b4826e2006f, "GDTF Version 1.2 Draft 1"): Table 3 FixtureType Name/ShortName/LongName/Manufacturer/FixtureTypeID; Table 69 `<Protocols>`, RDM child `<FTRDM>`, not mandatory; Table 70 FTRDM@ManufacturerID, @DeviceModelID (Hex); Table 71 `<SoftwareVersionID Value>` (Hex) under FTRDM; Table 72 `<DMXPersonality Value DMXMode>` (Hex, Name link to a DMX mode) under SoftwareVersionID; Table 1 Hex = hexadecimal notation, default 0 (0x prefix not stated; accepted, not required); description.xml is the static file name.

**Real files** (GDTF Share downloads, not committed): Elation Paladin Cube `<FTRDM DeviceModelID="0x1093" ManufacturerID="0x22A6"/>`; GLP JDC1 Strobe `<FTRDM DeviceModelID="0x0" ManufacturerID="0x676C"/>`. Neither has SoftwareVersionID or DMXPersonality children.

**Rules made here:** a 0 RDM ID, software version or personality in a file is not given (spec default + the JDC1 evidence); a missing FTRDM is no RDM data; an unusable value (not hex, too wide for 16/16/32/8 bits) is null and named in `problems`; an unreadable file is kept with its reason. description.xml is found as the browser import finds it (first entry whose last segment is description.xml, any case). Ranking: software-version tier (mode from that version only, not-mapped otherwise, with a note naming other versions' modes) before model tier (mode only when all versions agree, else `differs` + choices); within a tier Manufacturer, User, Unknown, then newest, then rid. Match query widths are the existing ones (rdm.UID/registry ManufacturerID, params.DeviceInfo DeviceModelID/SoftwareVersionID/CurrentPersonality). The endpoint takes decimal or 0x hex and refuses personality 0 (RDM personalities are 1-based).

**Tests:** 17 new, each failing first against a stub (proof lines in the four commit messages): reader (every field; no FTRDM; zero IDs and absent IDs; bad hex/too wide; unreadable: not a zip, no description.xml, malformed XML, wrong root, no FixtureType, oversized, missing file; case-insensitive name + BOM; real files, skipped when `$BENNY512_GDTF_SAMPLES` or /tmp/gdtf-samples lacks them), index (read at download, unreadable kept and sync still OK, pull reads; backfill once incl. after restart; Run backfills at start-up; LongName search in library and share), match (exact software version beats model-only and beats the Manufacturer-first order; personality → mode in every state; no match → empty incl. zero IDs; labels and descriptions kept; files not yet read counted), endpoint (503 disabled, hex and decimal, null echo, empty list, eleven 400 cases naming the parameter).
