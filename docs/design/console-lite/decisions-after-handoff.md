Each line names the spec section in `component-specs.md` and how the shipped UI now differs from it. Details and dates: the plan's Owner decisions and Progress rows I1–I2d2.

## Owner decisions of 2026-10-09 (I2d2)

- **§12 Fixture commands — one-shot.** Reset, Lamp off and every HOLD 0.75 s Control function send their value for a fixed **1 s** window (owner, 2026-10-09; I2d2 had a 5 s placeholder), then the channel returns to its previous value or the profile default; nothing is stored in the programmer or re-sent at Arm. §12 asks the engine to keep a "profile-declared hold for N seconds", but no profile here declares one (GDTF `DMXChangeTimeLimit` is not imported and is 0 in every real file), so the owner's 1 s applies to every command.
- **§12 / §7 what a command is (I2d3).** One server rule (`patch.IsCommandFunction`): every function of a Control-family channel, and any Reset or Lamp function on any channel. The UI reads it from the server; `/api/programmer/set` and Fan refuse such values (422, pointing at `/api/programmer/command`). Fan on the Control tab says Control channels are commands.
- **§12 progress (not in the spec).** A line under the Controls status, the same in every browser (server state): `SENDING <command> to <fixtures> — … in n s`, then `DONE … the channel is back to its previous value` or `STOPPED … cut short because output stopped`. Words and icons, not colour.
- **§12 / §1 Lease lost with "Hold last look".** A command in flight is not frozen into the held look; its channels hold what they return to.
- **§12 Disarmed.** The confirmation dialog states "Output is not live" and offers only Cancel (the action button is hidden); HOLD buttons are disabled with the reason in words. Nothing is queued for the next Arm.
- **§12 dialog words.** Armed, the dialog adds "Sent once: after 1 s each channel returns to its previous value. Nothing is kept in the programmer."
- **§15 Lowlight** now matches the spec: it dims only selected fixtures that are not highlighted, so with the whole selection highlighted it dims nothing; a visible line under Lowlight says what it covers. Since I2d3 it works per selection target: a selected cell that is not highlighted dims its own dimmer; a whole fixture dims all of them; highlight wins where they overlap (a fixture highlighted whole is not lowlit; a cell-less master dimmer is left alone while one of its cells is highlighted). Words: "Dims 2 selected cells not highlighted." / "Dims 1 selected fixture and 1 cell not highlighted."
- **§6 / §13 virtual dimmer (plan G1, extended I2d4).** Every fixture or cell with RGB colour mixing and no dimmer channel of its own has a virtual dimmer (no DMX channel; it scales that part's colour), also under a master dimmer. A cell under a master: its colour × its virtual level, then the master on top. A whole-fixture intensity control drives the master; cells are reached by selecting them. The Dimmer card says "virtual (scales colour)" in words. A part with neither still says it has no dimmer.
- **§14 presets:** "Store Control preset" is kept as is (owner, 2026-10-09), though Control values can no longer be held in the programmer.
- **§15 Locate** is NOT momentary and has no LOCATE source: it writes into the programmer (owner: no change).
- **§15 P (phone)** keeps the C6c one-line bar — selection count, Clear…, More. Highlight, Locate and Tests are in More (spec puts them on the bar). Highlight and Lowlight toggles keep More open so Previous/Next appear in place; the open menu ends above the fader bar and bottom navigation. Since I2d3 the More button says only "More" and, while Highlight is ON, "Highlight ON" (icon + words) shows under the count, so the count stays readable at 360 px.
- **§12 pattern applied app-wide.** Every question in the web UI (names, yes/no, Replace / Merge / Save as new, packet detail, Show tools, Fixture library) is a non-modal dialog below the master strip: Cancel focused first (name dialogs included), Escape closes and restores focus, DISARM reachable. Exception: the Settings full-reset "Benny512 has shut down" overlay (the process has exited).

## I2e (2026-10-09)

- **§16 Tests drive virtual dimmers (owner).** A dimmer test reaches a fixture or cell with colour mixing and no dimmer channel of its own through its virtual dimmer, by the I2d4 scope rule: a whole fixture through its master when it has one, a selected cell through its own virtual dimmer, an RGB-only fixture through its own (it is now offered dimmer tests). The per-fixture list says "through its virtual dimmer (scales colour)". When cells are tested, the tests' base state opens their fixture's master (as it already opens a whole fixture's dimmer) — confirmed by the owner in I2f.
- **§16 tiles:** glyph per test kind + ON/OFF word; Settings is its own `details`. (Masked-test note and Isolate: built in I2f, below.)
- **§16 P:** on a phone the Tests panel is a sheet below the master strip with Close and Escape; Tests stays under More (C6c/I2d2), so closing the sheet returns focus to More when the menu has closed.
- **§17:** Back / Next 60 px with glyphs, AUTO toggle "AUTO 8 s" (unavailable with the reason on a manual step), CURRENT word. The interval is the step's own (set in the editor), not an input on the transport. Edit is disabled while a sequence runs, so editing the running step does not arise. Editor rows: worded Move up / Move down / Add step after / Remove step, no drag handle (no drag at all).
- **§18:** horizontal faders (like §6 T/D in I2c1); the desktop fader keeps the app-wide 28 px param height. "RDM only" means the patch has the fixture committed to an RDM device; slot labels say "not reported" (an RDM slot read makes the fixture profiled, so a raw bank never has labels).
- **MIDI panel:** no layout in the package; restyled to the roles and glyphs only — link pill with midi-connected/disconnected glyph and a word, "Encoder n", fine glyph on Fine.
- **§15 P count pill:** with cells selected the count wraps "· 4 cells" to a second line inside the pill (a rounded box, not a capsule) instead of being cut off.

## I2f (owner answers, 2026-10-09)

- **§16 Tests open a tested cell's master (owner decision, was the I2e fill-in):** as they open a whole fixture's dimmer — colour tests on cells too — or nothing a cell test does can be seen. The programmer above still wins.
- **§16 dimmer test on unset colour = WHITE (owner):** wherever a dimmer test drives a fixture or cell whose colour is unset (a whole fixture with a master over cells at colour 0, the virtual-dimmer cases, a fixture with a real dimmer and RGB), that colour shows white for the test only — never written into the programmer, released when the test stops driving it; a programmer colour wins. Same rule as G1/I2d4 (a claimed virtual dimmer with no colour = white). The dimmer tests' Settings say so in words.
- **§16 masked test (built):** a test a higher layer overrides stays ON with "Overridden by SET on 2 fixtures." under its tile (icon + words + dashed rule); other layers are worded "a group fader", "Highlight", "a fixture command", "raw universe levels", "Universe Identify"; fixtures and cells are counted apart ("on 1 fixture and 3 cells"). The per-fixture list says "overridden by SET (Dimmer)". The data is the output engine's own per-channel composition.
- **§16 Isolate (built):** the kit's `.b5-choicecard--caution` card, "Isolate: drive only the tested channel — ON/OFF" with an explanation, below the test tiles (the mockup's place). Every channel of the tested fixtures that no test drives is held at 0; manual values still win. Choices where the spec is silent: a tested cell's master stays open under Isolate; a dimmer test's white still shows. Safety (owner): offered only while Armed with a test on (it says why otherwise); ends by itself on Disarm, on lease loss with either Settings choice (never held isolated) and when the browser that turned it on leaves, and with the tests; the card then says "Isolate ended by itself: output was disarmed." DISARM · BLACKOUT stays the strip's slab; the card is in flow, not a dialog.
- **§1 P strip (owner):** at phone widths, while ARMED, the show name is hidden visually instead of being squeezed to "D." (still read by assistive technology; Show tools' heading names the show). Other states keep it.

## I2g (owner answers, 2026-10-09 20:17)

- **§16 Isolate is never restored from a preset (owner).** A test preset saved with the old Rig Check's Isolate loads with Isolate OFF; only a live action on the card while Armed turns it on. (The stored field is still read so old show files load; it is not used.)
- **§16 fades (owner: no snap, overshoot or step).** A dimmer test's white on unset colour fades in and out with the tests' fade time like any other test change; a fixture or cell with a virtual dimmer and no colour set rises from dark to the test's white and falls back to dark. Choice made here: the white is held for the whole fade and released at its end, where the release changes nothing on the wire. With fade 0 everything still snaps.
- **§16 masked note is live (owner).** "Overridden by …" appears and clears in every open browser at once (within a frame of the change on the server; the browser then re-reads) for raw universe levels, Universe Identify, programmer SET/clear, group faders, Highlight and Isolate — no reload, no wait for the next tests read.

## C9 themes (2026-10-09 21:28:40 -0400)

- **theme-contract.md built.** Settings › Theme: Dark (default) or "Daylight — not for dark-venue checking", per browser, applied before first paint; custom themes edited in Settings (colour roles + preview intensity only), validated live and again by the server, failures in the contract's words ("Muted text on overlay is 3.0:1; needs 4.5:1."), "Theme needs changes" with Save blocked and a working Revert. The editor states the contract's limit: no certification; device black level and backlight need physical review.
- **Role set:** production roles = the package's plus I1b's bg-pressed, info-border, info-fill (scrim stays translucent and exempt, not themeable). bg-pressed and info-fill are **surfaces** in the pair checks; info-border joins the tone-outline ΔE set; bg-pressed and info-fill are under the 0.035 dark limit; canvas, surface, grid and XY pad are the "large regions" no brighter than overlay. Every Dark and Daylight pair passes; no value changed.
- **Base-file roles routed:** `bg-stale` is defined in both theme blocks (raised/overlay hatch in Dark — unchanged; raised/inset in Daylight); `border-accent`/`border-danger` uses became `accent-border`/`danger-border`; the undefined `--b5-color-border` became `border-default`.
- **Preview intensity** (`--b5-preview-max-brightness`): a custom theme on Dark may set (0, 0.15] and white × m must stay no brighter than overlay; on Daylight (0, 1]. **C9c (owner):** Daylight's default is 1 — the colour picker's field and swatches at full colour; the 0.12 default and 0.15 cap stay Dark-only, as the contract words them.
- **C9c (owner, 2026-10-09 23:12):** the C9 rules here are approved; a browser picks up another browser's edit of its custom theme at reload or its next Settings visit (no live update, by choice); the Dark changes (picker frame and error rules on the tone outlines, the three separators) stay.
- **Not in the package:** where custom themes live (station settings; use per browser), names/limits, export/import JSON, and what a browser does when its theme is deleted or stops passing (back to Dark, in words). Details in the plan's C9 decision line.

## J1 — owner bench test (2026-10-12; recorded 2026-10-12 14:10:22 -0400)

- **Layout (§3/§4):** MVR positions place fixtures automatically; the "Derive from positions" button stays for re-deriving with other settings. Unplaced is now only for fixtures without a position. Hand placements override automatic ones and never move.
- **Dark at Arm (state S, §6, §13):** with an empty programmer every intensity reads and outputs 0 when armed — real Dimmer and virtual dimmer alike — whatever the GDTF default; other attributes show their GDTF default as before. The Dimmer readout says why it is 0 ("dark at Arm"). Highlight, Locate and Tests still bring intensity up.
- **§19 fader bar — sub-fixture faders (owner):** a fixture type + mode with several intensity parts is drawn as one framed **cluster** in "Fixture types": the type's name on top, its **Master** fader first (labelled "Master"), then one fader per part labelled with its GDTF-derived word (JDC1: Beam, Plate; Rayzor 1960: Spark LED Strobe Module, RGBW Pixel). Each fader's group, slider and Release labels and its title carry the full "<type> · <part>". A part name may take three lines inside a cluster (read whole at 390 px); everything else in the bar is unchanged (dashed = untouched, "—", Release, Release all, collapse). Grouping is the frame plus the words, never colour. A type with one part keeps its plain fader; Groups unchanged.
- **Master vs part (behaviour):** both are ordinary faders — the most recently moved wins per channel. Without a real master channel (JDC1) the Master moves every part; ~~with one (Rayzor head) it moves that channel only~~ — superseded by J1b below: the Master moves every part.

## J1b — owner answers (2026-10-12 20:11; recorded 2026-10-12 20:44:11 -0400)

- ~~**Master overrides the subs**~~ (superseded by J1c below: the Master multiplies the parts) **(behaviour; refines the J1 cluster above):** a type's Master fader sets the whole fixture — the real master channel if any plus every part (Rayzor: head + RGBW pixels + SparkLED). A part fader moved after it takes its part; last moved wins per channel. Selecting a whole fixture in the Console (Dimmer, fan, Lowlight, dimmer tests) and stored-group faders do the same; I2d4's "whole fixture = the master only" is superseded.
- **Virtual dimmer rule refined (owner; refines I2d4 §9 "virtual (scales colour)")**: a cell gets a virtual dimmer only when its part has no real dimmer. JDC1 plate pixels have none — the Plate Module dimmer drives the plate; their Dimmer row is absent, and Dimmer on a plate pixel is refused in words. Rayzor pixels, Paladin beams and batten pixels keep "virtual (scales colour)". Lowlight dims a lowlit plate pixel through its colour; a Tests target on a plate pixel drives the Plate dimmer.
- **§19 fader labels — short type names (owner):** a plain type fader and a cluster heading show the short type name (GDTF ShortName, else derived: "JDC1 Strobe", "Proteus Rayzor 1960"); two modes read "Paladin Cube — 24ch" / "— 3ch". Parts still show their part word under the heading. Every aria-label, slider label, Release label and title keep the full name ("Custom GLP JDC1 Strobe · Plate").
- **Tests per-fixture note:** each overriding attribute is named once ("overridden by SET (Dimmer)"), however many Dimmer channels a whole-fixture test covers.

## J1c — owner answers (2026-10-13 09:31; recorded 2026-10-13 10:09:01 -0400)

- **The Master is a multiplier (behaviour):** a type's Master fader — and a whole fixture's Dimmer in the Console, a stored group's whole-fixture member, Lowlight, a whole-fixture dimmer test — sets the fixture's master level; part faders set each part beneath it; output = master × part; moving the Master never changes a part's level. "Master 0, parts at full: no output. Master full, SparkLED full, pixels 0: only the SparkLED." No double dimming: parts under the master dimmer's GDTF geometry are dimmed by that channel on the fixture; other parts are multiplied in software.
- **§19 fader bar — legacy profiles:** the Master of a type whose profile has no GDTF geometry tree says "Parts counted as dimmed by the master channel — re-import the GDTF to refine." in its tooltip and to assistive technology (visually hidden text). Nothing else in the bar changes.
- **§6 Dimmer card:** the master row says "master (multiplies the parts)" (words); "virtual (scales colour)" stays for a cell's own virtual dimmer. A whole fixture with a 16-bit master channel shows MIXED layouts (16-bit channel + 8-bit master) — owner question.
- **§15 Highlight on a cell:** opens the cell's fixture master and its part dimmer, so a highlighted pixel is visible on the rig (as Tests open them).
- **Stored groups:** a whole-fixture member is its master level; a cell member its own dimmer.
